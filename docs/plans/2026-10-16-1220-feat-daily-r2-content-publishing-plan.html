Product Contract

Summary

Curator, publisher and reader have separate jobs. Hermes chooses and edits stories. The publisher converts accepted Markdown into published data. Machine Herald renders that data and serves RSS.

Problem Frame

The current publisher commits digests into Quartz and deploys the newspaper for each accepted change. Both applications therefore depend on the website repository's content tree. Moving only the reader's file loader would leave publishing, recovery and Hermes instructions tied to Git.

Planning Contract

Key Technical Decisions

KTD1. Markdown remains authored; JSON is derived

Move the accepted archive to digests/ relative to the vault root. Keep local immutable accepted snapshots and source hashes. Use one neutral content module under hermes/ai-x-digest/content/ for parsing, wire validation, export and syndication. Give its Node CLI pinned dependencies independent of newspaper view imports. The app consumes its pure records and prose serializer.
JSON stores an allowlisted prose tree and structured editorial metadata. Resolve Markdown references once during compilation. Do not export private paths, original source files or raw HTML. Reuse the existing AST conversion instead of adding another Markdown parser. Governs R1, R2, R5, R8.
(session-settled: user-approved - chosen over RSS as application input: structured content keeps story and editorial metadata.)

KTD2. Private R2 with one published head

Use R2 Standard in the existing NK2984 account. Keep the bucket private and r2.dev disabled. Immutable edition and discovery objects use SHA-256 keys. A complete immutable manifest references their hashes and lengths. The mutable v1/head.json names the manifest hash, which is the content revision. The manifest does not contain its own hash.
The publisher uses the supported AWS SDK v3 S3 client. Separate infrastructure administration from a bucket-scoped Object Read & Write credential stored privately on Pluto. The app reads through its native binding. That binding grants write capability too. Enforce a get/head-only module interface and expose no mutation route. Governs R3, R7, R8. See R2 API and consistency sources.
(session-settled: user-directed - chosen over repository-bundled digest data: publishing must not require redeployment.)

KTD3. Recover the publication before restoring local files

Keep the existing common Pluto publication lock. Version new requests and receipts. Requests identify exact staged bytes, previous accepted source hashes and the expected published manifest/ETag. Reject legacy Git-shaped requests after cutover. Record the compiler code revision separately from content identity.
Before publishing, freeze the candidate, journal source promotion, upload immutable objects and read back exact bytes. Create immutable keys with If-None-Match. Replace head last with If-Match against its previous ETag, or If-None-Match for bootstrap. A failed precondition is a conflict. Never force an overwrite.
After a lost response, inspect head. The intended revision resumes verification. The predecessor permits retrying the same conditional write. Another revision stops recovery. Do not infer failure from a missing Git commit or one negative read. Preserve manual edits and accepted snapshots. Governs R7, R8, R13. The supported conditional API and delayed-write caveat are in the R2 sources.

KTD4. Render each request from one content revision

Convert the existing daily Worker to Astro server rendering. Pin @astrojs/cloudflare@14.3.3, compatible with Astro 7.3.8 and Wrangler 4.151.0. The latest adapter requires an unrelated Astro upgrade. Use the pinned adapter's Worker entrypoint and current Cloudflare bindings. Disable sessions and image transformations, so the migration adds no KV or Images dependency.
A request selects head once, then reads only that immutable manifest and its referenced objects. Remove Git subprocess loading, getStaticPaths and the global latest-content Promise. Home loads one edition. Archive and sitemap use catalog metadata. Search uses its materialized text index. Never load 179 edition bodies for one page.
Keep mutable reader routes and RSS uncached initially. Static hashed fonts and CSS remain assets. Check that old prerendered pages cannot shadow runtime routes. A valid catalog missing a date returns 404. Missing or invalid referenced publication data returns a controlled 503, never an empty successful newspaper. Governs R3, R4, R5, R7. See the pinned adapter source.

KTD5. Materialize full RSS without newspaper styling

The neutral content module writes the complete RSS artifact during publication. Its item granularity and identity follow R6. The manifest pins that artifact alongside edition JSON. The existing app endpoint streams it, so a feed request does not render the full archive.
Use shared safe prose serialization. Include full active content, image alt text/captions/credits/sources and corrections. Express charts as accessible tables retaining title, unit, qualifiers and every value. Newspaper fonts, CSS, layout classes and SVG drawing stay in the app. Archived stories keep their article routes under R5 and follow the current active-feed policy. Governs R4, R6, R7.

KTD6. Keep one publication and delivery lifecycle

Replace the Git-specific stages with accepted, source-promoted, objects-verified, published, readerverified, deliverypending and complete. The receipt records exact object hashes, previous/intended generations, compiler revision and live proof. Content success requires live reader verification. Failed verification leaves the receipt at published with the verification error recorded. It blocks delivery and resumes verification of the same publication. Quartz main-result no longer gates digest success.
Keep the existing delivery-begin, delivery-complete and delivery-resolve controls. An ambiguous deliverypending receipt blocks another send. A completed receipt is inert. Operator backfill/correction requests cannot enter scheduled delivery. Hermes history and novelty checks use the last seven published accepted editions. Pending candidates remain separate.
Resolve outstanding publication, recovery and delivery actions on old Git receipts before activation. Retain their resolved historical records. Never reinterpret their commits as R2 generations. Governs R8, R9, R10.

KTD7. Use exact Cloudflare redirects for the old website

Generate a dedicated Bulk Redirect list from the complete old emitted URL inventory. Use exact 301 mappings, preserve query strings, disable subdomain and suffix matching, and target final working URLs directly. Edition aliases target their dated edition. The root, month and year indexes target /archive/.
Cloudflare Free allows 10,000 redirect URLs, enough for this inventory subject to existing account usage. Verify proxied DNS and redirect permissions before activation. Preserve the GitHub Pages origin and unrelated rules. Do not assign the main hostname to the daily Worker. A private mapping file and GitHub Pages meta-refresh pages do not satisfy R12.
Fragments never reach the redirect service. Inventory current emitted heading fragments and retain compatible target anchors where they identify digest sections. Do not invent mappings for missing dates. Governs R11, R12. See Bulk Redirect documentation.
(session-settled: user-directed - chosen over keeping a frozen Quartz digest archive: the main website must exclude the whole digest section.)

KTD8. Backfill first, switch writers once, remove Quartz last

Inventory accepted sources, emitted aliases, source hashes and feed identities before moving files. Baseline inspection found 179 editions and nine index notes. Recompute counts at execution and include any newer accepted edition. Use an explicit pinned legacy snapshot only for backfill. Preserve legacy content without fabricating story IDs.
Verify the replacement on isolated preview resources first. Cut over production between scheduled runs. Fence scheduled and manual digest starts, drain old tasks, and hold the common lock across the final import, production runtime deployment and producer switch. Verify the new reader before restoring normal publication. If the switch fails, restore the previous compatible reader and producer before releasing the fence. Restore the original job definition and enabled state before the next scheduled run. Install sync exclusions before relocating sources. Do not expose a lasting dual writer.
Enable and verify redirects before removing Quartz inputs. Only the initial code/infrastructure change and the one-time main-site removal require deployments. Later editions use KTD3. Governs R1, R3, R5, R9, R11, R12, R13.

KTD9. Rollback retains accepted history

Keep previous manifests, objects, private source snapshots, installation backups and the last website commit. Do not run automatic R2 garbage collection in this migration. On a runtime defect, restore a schema-compatible Worker version. If content must be rolled back, conditionally select a retained verified manifest and record the action.
Keep newer accepted editions and receipts for repair and roll-forward. Do not reinstall the static reader or Git-writing producer after R2-only editions exist. A redirect failure before removal postpones removal; it does not justify silently discarding R12. Governs R5, R7, R13.

The digest publisher changes its request and receipt schema. Hermes prompts, validators, history lookup and recovery must switch together. Ordinary note publishing remains a separate operation under the common lock.

Code provenance and content provenance become separate. The code release manifest identifies the Worker build. The reader's provenance endpoint identifies its selected content revision. Daily publication verification compares live pages with accepted content, rather than local static build output.

The main website needs one content-removal release and Cloudflare redirect configuration. R2 provisioning and redirect administration need permissions beyond the existing daily deployment token.
