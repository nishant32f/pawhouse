  3. R16. Support sourced images and simple charts. A visual is exactly one image or bar. Both require a caption and a source_url matching a real adjacent source in the same story. Images require an HTTPS src without credentials or control characters, positive integer width/height, nonempty alt text and credit. Images render natively without a server-side downloader. Bars require title, unit and 2 to 4 comparable points. Each point has a label, a finite nonnegative number, and an explicit qualifier from exact, approximate, greater-than, at-least. At least one value is positive. Render labels, qualifiers, data, captions and credit as escaped text. No authored HTML, SVG, CSS, JavaScript or second public writer checkpoint. The chart must preserve lower bounds and approximate numbers.

Hermes selects relevant original source media or chartable figures while inspecting sources, records their provenance privately, and writes the optional fields into the accepted Markdown. Preserve all useful qualifications and source support. Reuse exact accepted metadata on retries. No new collector, image generator, notification channel or formatter service.

Product Contract

Summary

Publish daily editions in a dedicated newspaper reader. Keep the existing vault as the authoring source and the main website as the knowledge library.

Problem Frame

The content release removed repetitive themes and forced takeaways. Quartz still surrounds the digest with note navigation and graph furniture. Mixing two reading styles within that site would make the destination unclear.

Key decisions

Newspaper reader. (session-settled: user-directed; chosen over briefing, feed, and magazine after seeing examples.) Governs R1, R2, R3.

Separate app and subdomain. (session-settled: user-approved; daily.nishantkhurana.me chosen over digest-only Quartz styling to give the reader a consistent identity.) Governs R9, R12.

Key technical decisions

KTD1. Keep the reader in an independent app directory

Create apps/daily/ in Pawhouse with its own package, lockfile, build, styles, and deployment workflow. Keep hermes/ai-x-digest/ as the canonical producer package.

The reader uses Astro static output. It reads only committed digest Markdown from content/digests/ at build time. This instantiates R9's settled separate-app decision. No Quartz layout/component changes implement the reader.

KTD2. Parse one authored Markdown edition

Continue authoring digests/x-ai-YYYY-MM-DD.md in the public vault and syncing that file into content/. Do not create a second authored article tree or require a JSON writer checkpoint.

For newly identified editions, add an explicit format version editorial-v2. Each H2 story and H3 brief receives a hidden comment containing an immutable safe ASCII ID. The marker belongs immediately after its heading. Metadata and Markdown prose are the source; parsed records and HTML are generated output.

Record Contract
Edition Date from the validated filename/frontmatter, title, format version, and ordered story blocks. Pin the daily date once in Asia/Kolkata.
Story Marker such as <!-- story-id: anthropic-monorepo -->, headline from the heading, opening paragraph as summary, remaining prose and adjacent sources as body. First full story is lead. IDs match [a-z0-9]+(?:-[a-z0-9]+)* and are unique within the edition.
Exclusions Navigation and Backlinks sections are vault furniture, not stories. The reserved In brief section contains H3 brief records.
Source handling Preserve actual adjacent source links and attribution. Escape raw HTML and reject unsafe link schemes. Interpret the one allowlisted ID comment as metadata, never executable HTML.
Legacy Unversioned and editorial-v1 editions render as whole editions with existing sources. They do not gain invented individual article routes. Initial production adoption adds reviewed IDs to the latest accepted edition and changes its format to editorial-v2 without rewriting its prose. Keep the original source privately.

Retain IDs when headlines change or stories move. The revision validator compares old and new editions and requires an explicit correction when an existing ID disappears. Never regenerate IDs from headlines or array positions.

For a removed published story, keep its original ID and prose in an archived block in that same edition Markdown, with a correction note. Omit it from current cards and previous/next navigation; retain its existing article URL. No secondary authoring store is introduced.

The preview's four IDs are illustrative and do not modify public Markdown. U1/U5 implement the identity and verifier support. Actual production marker adoption remains part of authorized U6 activation.
